# Session prompt — multi-track timeline architecture (plan #13; operator-picked next arc, queued 2026-07-13)

The operator closed the editor-suite slices 1–8 arc (commit `7dada7f`, ADR
0064/0065 + amendments — READ ADR 0065 FIRST, it holds the timeline's
grammar) and picked plan #13 from `feature-implementation-plan.md` (repo
root, THEIR file) as the next arc, with two rulings in their own words:

- **"mimic adobe or tiktok"** — the Premiere/CapCut multi-track shape:
  track headers in a left column (eye/lock/mute + name), lanes to the
  right, wheel scrolls, zoom around the pointer, clips as blocks.
- **"keep the independent track: if it get generated by ai it must have
  their own track, if it by me it must get its own track"** — the
  AI-vs-operator separation is THE architectural rule, not a caption
  quirk. The caption lanes ("auto" vs "yours", ADR 0065 amendments 3–4)
  are the existing embodiment: generalize it. An AI artifact and an
  operator artifact NEVER share a track.

Plan #13's own requirements: independent tracks; drag clips between
tracks; correct layering; lock, hide/show, mute per track; smooth
scrolling and zooming; future-ready for nested timelines and grouped
clips. Their sketch: Video 2 (B-roll) / Video 1 (Main) / Captions /
Images / Music / SFX, each with 👁 🔒 🔇.

## What EXISTS today (verified in `crates/app/src/editor.rs` 2026-07-13)

- `ui_timeline` paints HARDCODED rows, not a track model: ruler (18px),
  video filmstrip track (26px, the Prepare frames), caption lanes auto+
  yours (15px each, one block per unit), burn-line rail (6px), speaker
  seat lanes + voice/evidence row (flex height), camera-cut zone (20px).
  Chrome const = 103. Every row is bespoke painting + `ui.interact`
  regions; gestures live in `TimelineDrag` (pointer-tracked, applied
  before drawing each frame — keep that pattern, it survives live
  reshaping).
- **No zoom, no horizontal scroll**: `t_to_x` maps the whole clip to the
  strip width (deferred in ADR 0064 as "#13's work"). This is the single
  biggest usability ceiling — tiny caption blocks fall back to move-only
  below 24px, razor precision is pixel-bound.
- Per-track state that already exists: `razor: RazorState` (+ cut_marker),
  `manual_units`/`manual_places` (the operator caption track), transcript
  units (the AI caption track), `frames` (video thumbs), `plan` (camera
  cuts), `speakers` (seat/voice lanes). `show_captions` is an overlay eye
  in the toolbar, not a track flag. No lock/mute anywhere.
- Render reality: main video+audio and the TWO caption streams render
  honestly today. **Images (#5), Music (#6), SFX, B-roll (#14) have NO
  render machinery** — their tracks cannot honestly exist until their
  ffmpeg arcs land (the razor's per-piece trim/concat and a future
  amix/overlay stage are the natural homes; see the razor's
  `build_camera_filtergraph` audio pairing for the pattern).

## Sharp edges for the grill (don't assume — ask, or decide honestly on "automatic")

1. **Scope slicing.** The honest first slice is the track SHELL: a
   `Track` model (kind, label, eye/lock/mute, height), the header column,
   zoom+scroll viewport, and REHOMING the existing rows into it (Video /
   Captions-AI / Captions-yours / markers). Music/Images/B-roll tracks
   should appear WITH their render arcs, not as dead UI — an unmutable
   Music track is a lie. Confirm the operator accepts tracks arriving
   incrementally.
2. **Eye/lock/mute honesty per track, today**: eye on a caption track =
   that stream doesn't burn (easy, honest — thread through RenderSpec);
   lock = ignore that track's interactions (trivial); mute on Video 1 =
   the export goes silent?? — render work (volume=0 / -an), grill whether
   mute waits for the audio-mixer arc (#7's future section).
3. **Drag between tracks** (plan #13) vs the operator's separation rule:
   same-kind moves (Video1↔Video2, image↔image) are fine LATER; dragging
   an AI caption onto the operator's track would change OWNERSHIP —
   grill whether that's "take over this caption" (copy to manual, delete
   from AI) or forbidden. Do not silently blur the boundary they ruled on.
4. **Zoom/scroll viewport**: zoom factor + scroll offset feeding EVERY
   t_to_x/x_to_t (they're closures today — become viewport methods);
   ctrl+wheel zooms about the pointer, wheel/shift-wheel scrolls,
   scrollbar when zoomed; the filmstrip must pick thumbs for the VISIBLE
   range; keep gestures/snap tolerances in POINTS not seconds (SNAP_PX
   already is). The playhead grab handle + marker priority order
   (playhead > markers > blocks > scrub) must survive.
5. **Persistence**: track flags + future track contents (music files,
   images) belong in project.json's Clip eventually — pre-register the
   schema question in the ADR before building track kinds that need it.
   Editor-session-only state (like manual captions today) is acceptable
   for slice 1 — say so explicitly in the ADR.
6. Layering for the render (B-roll above main) is #14's ffmpeg overlay
   work — the track ORDER in the UI should be right from day 1 (top =
   above), even while only one video track exists.

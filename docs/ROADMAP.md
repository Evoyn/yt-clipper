# Roadmap

Milestones build tracer-bullet style: M1 threads every subsystem at minimum depth; later milestones deepen one subsystem each. Order confirmed 2026-06-11.

- **M0 — Skeleton** ✅ (2026-06-11): cargo workspace (`app` egui shell on egui 0.34, `core` domain, `ingest`, `transcribe`, `detect`, `render`), hello-window builds and launches, domain round-trip test green. Outstanding: operator must run `scripts/fetch-sidecars.ps1` (downloads gated behind operator approval).
- **M1 — Tracer bullet** ✅ (2026-06-17): local file → audio extract → whisper transcript → manually picked time range → default stacked Layout (hardcoded Crops) → one caption preset → NVENC export. First real clip rendered end-to-end (`workspace/clip/export.mp4`, 1080×1920) on a YouTube-pulled 360p segment (1080p deferred to M2 — see below). Added a `--headless <video> <start_s> <end_s> [en|id|ja]` app mode for render iteration without GUI clicking. GUI builds; interactive path not yet exercised. Post-render polish: fixed overlapping captions (end-cap each line at the next line's start) + line-break on >1 s silence, and made the transcription **language operator-selectable** (En/Id/Ja, UI dropdown + headless arg). **Known limitation:** whisper transcribes the loudest speech in the single mixed audio track — it does NOT isolate the streamer's mic from in-game voices, so clips with prominent game dialogue caption the *game* (the 360p test clip did). True streamer-only captions need a vocal-separation pre-step (e.g. an `ort`-hosted source-separation model) — future work, affects detection quality too.
- **M2 — YouTube ingest** ✅ (2026-06-18): audio-only download + chat-replay JSON at import; padded segment download when a Moment is promoted (ADR 0001). _Ingest reality (found in M1): yt-dlp needs a JS runtime (deno) on PATH or it 403s; its native downloader works but the ffmpeg `--download-sections` path hangs with no read-timeout, and googlevideo throttles the DASH 1080p stream from some regions — so "download only the padded segment at full quality" is the real engineering problem here, not a given._ **Resolved 2026-06-17 (ADR 0006), full two-phase end-to-end ("M1 but the VOD is a URL"), spike-validated:** fetch the Segment as **HLS via `--extractor-args youtube:player_client=web_safari`** (token-free m3u8 in the 2026 SABR era; `--download-sections` grabs only the in-range fragments natively, no ffmpeg seek), `-f best[height<=1080][vcodec^=avc1]` (1080p60 H.264, itag 301), **deno pinned as a sidecar** (nsig), `--socket-timeout` + hard cancel. Spike got a clean 60 s 1080p clip in ~5 s/37 MB. ffmpeg only muxes/cuts; pad the request and read the true in-segment offset via **ffprobe** before the frame-accurate export cut. Persist `project.json` per `video_id` (Creator deferred to M5/M6); fetch chat raw at import and tolerate its absence (parsed in M3); add a **Cancel** that kills the child process tree (full job-queue UX stays M7). **Built + verified 2026-06-18 (`018e38a`):** URL→clip end-to-end on a real 1080p60 VOD. Import audio = itag 140 via `android_vr` (the one client ADR 0006 left to validate inline — confirmed). The in-segment offset is deterministic: yt-dlp resets the section timeline so pts=0 maps to the requested start (spike-confirmed `start_time=0` + negative-PTS keyframe lead-in), so offset = left-pad, self-correcting via ffprobe `start_time`. Two upgrades beyond the M1 caption baseline: **DTW word timestamps** (large-v3 alignment heads, `t_dtw`) for tight per-word sync, and **one-word "huge-word" captions** as the new default. Re-importing a VOD reuses cached analysis audio. **Carried-forward limitation (unchanged):** whisper still captions the loudest voice in the mixed track (the game, not the streamer) — vocal separation is the fix; weigh before/within M3.
- **M3 — Detection ensemble** ✅ (2026-06-18): chat-rate spikes + loudness + excitement lexicon → scored Moments; review UI = waveform + transcript + audio playback (ADR 0002). **Designed in a grill-with-docs session → ADR 0007** (cheap whole-VOD discovery vs whole-VOD whisper; vocal separation does NOT gate M3). Two phases: **discover** (cheap, no GPU) bins the VOD (1 s), robust-z-scores each signal so spikes are relative (constant game loudness sits at z≈0), **max-pools loudness** (peak-preserving, so a brief scream surfaces rather than being averaged under sustained talk) and mean-smooths chat, weighted-combines, peak-detects + NMS into non-overlapping lead-windows (chat lags the event), top-N; **refine** transcribes each candidate once with a *resident, text-only* whisper (`Transcriber::load_text_only` — no DTW, which else aborts on sparse music windows) and scores the excitement lexicon (z-scored across candidates). Signals stored unblended (`combined_score` renormalizes → retunable). The Moment is now the hub (CONTEXT.md: a Clip is a promoted Moment): import → **Detect** → ranked review list (per-signal σ breakdown) + waveform (loudness + chat overlay + clickable markers) + transcript panel + audio playback (rodio, no scrubbing per ADR 0001) + manual marking → promote. Defaults tuned on a real 66-min VOD; **operator-verified in the GUI** (playback/transcript/waveform; the jumpscare-capture fix above came from that review). **Carried-forward / future detection signals:** a **speech-emotion / sentiment model** (operator request — spikes find *loud*, not *emotionally* clip-worthy: a laugh and a rage look alike); **chat-content excitement** (emote/laughter/caps mining, not just rate); **vocal separation** (still the mixed-audio fix — lexicon reads the loudest voice); and the promote-path still uses DTW, which could abort on a no-speech clip (rare; operator picks speechful ranges).
- **M4 — Arousal Signal (SER)** ✅ (2026-06-18): a CPU speech-emotion model adds an *arousal* Signal in refine — the emotional activation of the streamer's voice — so loud-but-flat moments (game explosions, music, cutscenes) stop ranking like real reactions (ADR 0008). audeering `wav2vec2-large-robust-12-ft-emotion-msp-dim` ONNX via `ort` (CPU execution provider — no GPU staging), 16 kHz (matches `analysis.wav`, no resample), behind the `ser` cargo feature so default builds need no ONNX Runtime binary; per candidate, slide a 4 s window and **max-pool** arousal, z-score across candidates, weight into `combined_score` (unblended, retunable — ADR 0002). **Mixed-audio gate PASSED** on the real VOD `ZSegfmsrYmE`: whole-VOD arousal has a wide range (quiet ~0, median 0.67, max 1.10 — the game does not drown the streamer), genuine reactions peak high at only moderate loudness, and max-pool demotes loud-but-flat candidates — so vocal separation stays deferred. **Verified through the real pipeline** (`--detect --features ser`): the `arou` column populates and reranks sensibly (the 43:36 reaction → #1, the loud-but-flat 45:23 → #6). **Whole-VOD arousal _discovery_ deferred** (the pre-committed fast-follow): ground-truthing it first (off-diagonal `arousal_scan` + the `arousal_adds` transcript probe) showed ~50% precision, with false positives dominated by the game's own emotional cutscene audio — discovery hits the mixed-audio limit refine's loud/chatted candidate set avoids, so it is gated on vocal separation. Refine-arousal ships; the few genuinely-missed quiet reactions fall to widening top_n / manual marking until then (ADR 0008 Outcome).
- **M5 — LLM judgment Signal** ✅ (2026-06-19): a local GGUF model (**Qwen2.5-7B-Instruct Q5_K_M**) reads each refine candidate's transcript and scores clip-worthiness, **explicitly told to discount scripted game narration** — the semantic judge the heuristics can't be (ADR 0010). Slots into refine exactly like arousal: a `Weights.llm` term (defaults rebalanced to chat .30 / loud .20 / lex .10 / arou .15 / **llm .25**), a per-candidate 0–10 score z-scored across the candidate set, the existing sort reranks (signals unblended, retunable — ADR 0002). **Build pivot:** whisper.cpp and llama.cpp can't co-link (both vendor `ggml` → LNK1169), so the llama.cpp inference (`llama-cpp-2` v0.1.150, CUDA; GBNF-grammar-constrained JSON; greedy/temp-0) runs **out-of-process** in a new `yc-llm-judge` binary that links llama only; the app shells out per detect (candidate batch as JSON over stdin → verdicts on stdout) **after** the whisper `drop`, and the child frees its VRAM on exit — sequential GPU staging across the process boundary. `yc-detect::llm` keeps the pure shared pieces (prompt + mitigation, lenient parser, z-score `apply`, the IPC structs). **Verified:** a standalone judge smoke-test scored a streamer reaction 8, a hype/win 10, a **scripted-cutscene line 0 despite arousal 1.1 — the ADR 0009 #11 antidote**, and menu-reading 0; a full headless `--detect` then ran end-to-end (whisper refine → app spawns judge → the `llm` column populates and reranks). The GGUF download (~5.4 GB) is operator-gated. **Also this session (carried-forward item 1):** removed whisper's abort callback — handing whisper any abort hook breaks ggml-cuda graph batching and collapsed throughput to ~5% util (a hung-looking detect); Cancel now falls back to between-candidates (and still kills downloads). **Follow-ups:** detect from the GUI competes with the wgpu render loop on the single 8 GB card (run headless, or throttle the repaint while a GPU job runs); `CancelToken::is_cancelled()` locks a Mutex per call (→ AtomicBool); whole-VOD arousal discovery still gated on vocal separation (ADR 0008).
- **M6 — Auto-detect framing** ✅ (2026-06-19, ADR 0011; reframed automation-first): the LLM judges which Moments are clip-worthy, so vision-ML frames them — no manual drag editor first. At Promote, sample frames from the Segment we already download, run **Ultraface RFB-320** (~1 MB, hand-decoded on the existing `ort` — not YuNet, which couples to OpenCV), cluster the **static Facecam**, and pick the `Layout` three ways by the face's size/position: small off-center cam → **Stacked** (gameplay + facecam), large centered cam (talking session) → **FullFrame on the face**, no persistent face → **FullFrame gameplay**. Detected **per Segment** (the cam moves between gameplay and talking sessions — no whole-VOD cache), per-VOD now (Creator-level caching waits on `creators.json`). Replaces the hardcoded `pipeline.rs::layout_for`; new `yc-frame` crate splits pure geometry (clustering + the three-way decision + box→Crop expansion, always-compiled + unit-tested) from the Ultraface inference (behind a `face` feature), mirroring the arousal split. Absent feature/model or no face → safe FullFrame-gameplay fallback. **Verified headless** on two real 1080p gaming Segments (Windah Basudara): Ultraface found the static Facecam at persistence 0.95/1.0, chose Stacked, and the facecam Crop tracked the real bottom-right cam — both rendered correct 1080×1920 clips via the M1 NVENC path. Model `version-RFB-320.onnx` (1.27 MB). **Nudge editor increment shipped (2026-06-19, ADR 0012):** a manual escape hatch over the auto pick — a floating egui editor where the operator overrides the Layout type (3-way), pans/zooms each Panel's Crop, drags the Seam, and scrubs a few preview frames, watching a **live egui UV-composite** (each Panel drawn as a UV sub-rect of one extracted source frame — pixel-exact for the render geometry, no ffmpeg per nudge, no GPU contention). This **supersedes ADR 0005's** ffmpeg-filtergraph framing preview (the residual gap, burned captions, is immaterial to framing and still appears on Render). Atomic Promote split into **Prepare** (download + auto-frame seed + preview frames) and **Render** (the operator's nudged Layout; whisper deferred + cached so re-renders are NVENC-only); headless auto-forwards Render with the auto Layout, preserving the old one-shot path. Verified headless on `ZSegfmsrYmE` (split preserves M6 auto-framing exactly); live drag UX is the operator's interactive follow-up. New pure, unit-tested `yc-frame` editor geometry (pan/zoom/seam-refit/seeds).
- **M7 — Caption Styles** ✅ (functionally complete 2026-06-28): rolling-pop, huge-word, karaoke-fill presets; per-Creator defaults; JA chunk grouping (ADR 0003/0004). _Caption **timing** is now solid groundwork for styling: gap-fill from whisper's DTW onsets (each word fills to the next onset, capped at a max-hold, floored at a readable minimum), with the RMS envelope demoted to a near-silence drop only — ADR 0013, from diagnosing the `9-X80Ozwo1I` 34:10–34:40 "missing / too fast / too slow" complaint, which turned out to be timing re-derivation from the mixed envelope, not vocal masking._ **Done (2026-06-28): all three genres now build** — `karaoke-fill` implemented in `yc-render::ass` (ASS `\kf` per-word fill synced to the DTW onsets; inline `\1c`/`\2c` so the unsung text is the primary colour and the sung sweep is the accent, independent of the Style line), libass-verified by a real burn (the gold sweep animates word-by-word). **Caption style is now selectable** — a GUI combo + a headless `[huge|rolling|karaoke]` arg thread the genre through `Job::Render`; font size is genre-aware (150 for huge-word, 96 for the multi-word genres). **Per-Creator caption-style defaults done (2026-06-28, ADR 0016):** a global `workspace/creators.json` (`core::CreatorStore`) remembers each Creator's Caption Style — importing a known Creator's VOD seeds the render's genre, each render saves it back (operator overrides win). Robust to whisper's exact JA spacing (chunks by char budget over trimmed tokens); a real-JA-streamer render is the natural validation when JA content appears. **Still open in M7:** **applying** the other per-Creator defaults (language — recorded but needs a Creator-aware import UI; seam/crops — reserved, tangle with M6 framing). With these, **M7 is functionally complete** — the remaining work is M8 hardening.

## Standing constraints

- Offline (see CONTEXT.md): network only for user-initiated ingestion.
- Finished VODs only — no live-stream clipping in v1.
- Single 8 GB RTX 3070 Ti: GPU stages strictly sequential, never concurrent.
- Languages: English, Bahasa Indonesia, Japanese end-to-end (transcription → captions).
- Persistence: a **stream folder per VOD** (`workspace/<creator>/<stream-title>/`, ADR 0015) — rendered Shorts at its root, intermediates + `project.json` under `data/`. The global `creators.json` defaults store is still deferred (lands with M7); no database.

## Future directions (beyond v1)

Operator-brainstormed directions, not yet milestones — promote to a numbered milestone + ADR when pursued.

- **Better speech isolation / detection over game audio** (revisits "Vocal separation", post-ADR 0014) — htdemucs was built, productionized into the caption path, and **rejected for captions** (it is a *music* separator: it leaves SFX/BGM bleed **and** cuts real spoken words — operator-confirmed by ear; ADR 0014). The validated in-process `ort` runtime is shelved for the one job lossy separation suits: **whole-VOD arousal _discovery_** (ADR 0008's gate — score the streamer not the game). **If/when revisited, benchmark a _speech-aware_ model on a genuinely-masked clip — not another music separator.** Best candidates, in recommended order:
  - **Mel-Band Roformer / BS-Roformer** — current SOTA vocal isolation (Ultimate-Vocal-Remover grade), dramatically cleaner than htdemucs; still a music model so some speech-cutting remains, ONNX → reuse `ort`. **Best for heavy-music isolation.**
  - **DeepFilterNet** — real-time speech *enhancement*, **written in Rust** (no ONNX glue — fits this pure-Rust stack natively), preserves words; tuned for noise so very loud musical BGM is the harder case. **Best fit for the stack.**
  - **Silero VAD** (tiny ONNX) — if the goal is just *detecting* when the streamer is talking (speech-presence gating), not isolating.
  - Caveat (ADR 0014): even perfect isolation will **not** fix the streamer's **dialect/accent** errors — the real caption pain, handled by the dialect-correction store. Better isolation pays off only on **genuinely-masked** clips (music actually burying the mic — not yet found in tested content) and **arousal discovery**.
- **ASR engine upgrade (Qwen3-ASR) + selectable caption model** — confirmed direction 2026-07-02 (operator: "I want the best model for Indonesian and English"). Alibaba open-sourced **Qwen3-ASR** (Jan 2026): 0.6B/1.7B, 52 languages **including Indonesian + English**, built-in timestamp prediction, an explicit robust-over-music/song training claim (our masked-game-audio failure mode), and official **GGUF running on llama.cpp** — the runtime `yc-llm-judge` already ships, so it slots in as a `yc-asr` sidecar with no whisper.cpp link constraints. Released alongside it: **Qwen3-ForcedAligner** — align the *corrected* caption text against the audio for karaoke timing instead of inheriting the decoder's DTW spans for the garbled version. Plan, in order:
  1. **A/B trial before anything touches the render path**: a minimal sidecar hosting Qwen3-ASR-1.7B GGUF, run against whisper-large-v3 through a `caption_diag`-grade harness on the two documented hard clips (the "Diskusi biasa" fast-slang clip + the eh-pile clip #7) **and** a clear EN/podcast control — the operator judges ID + EN side by side. Whisper stays the baseline until beaten *on our clips*.
  2. **The ADR 0033 gate**: an ASR swap re-keys every curated garble (the dialect stores' `wrong` entries are whisper's exact output). A switch must never silently invalidate curation — either dialect stores get stamped/scoped per decoder, or the swap rides the **time-anchored curation** migration (corrections keyed to VOD time spans, not surface garbles — the harvest notes already carry timestamps).
  3. **egui model picker**: an "ASR model" combo (engine+model, discovered by scanning `models/`), remembered **per Creator** like Caption Style (ADR 0016) — per-Creator sticky, not per-render whim, precisely because of the coupling in (2); the UI warns when the selected model differs from the one the Creator's store was curated against. v1 is a two-way switch (in-process whisper vs the Qwen3-ASR sidecar).
  - Also on the free-model radar (2026-07): judge upgrade Qwen2.5-7B → **Qwen3-8B / Qwen3.5-9B** (drop-in GGUF, better ID+EN); **Meta Omnilingual ASR** (Nov 2025, 1600+ langs) and **Dolphin** (SEA-focused) as ID-capable ASR fallbacks; **pyannote community** for the multi-speaker future. All fit the 8 GB / 16 GB laptop.
- **Active-speaker / dynamic framing** — extends M6's *static* facecam auto-detect to *moving* subjects (confirmed direction 2026-06-19):
  - **Multi-person (podcast, 2–3 on screen):** frame/cut to whoever is *talking*. Face detect + track (YuNet/SCRFD + a tracker) + **active-speaker detection** (audio-visual — lip/mouth motion + voice, e.g. TalkNet / Light-ASD via the `ort` runtime) → smoothed pan/zoom of the 9:16 crop onto the active face (cut-vs-pan logic). Pairs with **speaker diarization** (the mixed-audio thread, also future): per-speaker audio + visual ASD = robust "frame the talker," and the two hard problems reinforce each other.
  - **IRL / vlog** (IShowSpeed-style: handheld camera, public spaces, fast motion): lock onto the streamer (face-ID) + saliency/motion to follow the action in the moving frame.
  - Broadens scope past the current gaming-VOD domain (gameplay + static facecam) toward talking-head / IRL content — v2-scale; revisit the "Finished VODs only / gaming" framing then.
- **Multi-speaker captions (collaboration / co-op streams)** — when 2+ people talk (a guest, a Discord call, a co-op partner), caption **each speaker in a different colour** and attribute each line to the right person. The hard part is **"who said this line"** (speaker attribution), and it must be **tuned to attribute near-perfectly** before shipping — a wrong colour is worse than no colour (operator's bar).
  - **Audio:** speaker **diarization** (pyannote.audio-grade embeddings + clustering) or speaker-embedding (ECAPA-TDNN / Resemblyzer) over whisper's word timings → label each `CaptionUnit` with a speaker id → map ids to caption colours.
  - **Audio-visual (the robust version):** pair diarization with **active-speaker detection** (the framing thread above — lip motion + voice, TalkNet / Light-ASD via `ort`) so "who is talking" is grounded in both the audio *and* who is on screen; the two hard problems reinforce each other.
  - Render side: a per-speaker colour on the `CaptionStyle` — extends **M7 Caption Styles**. Shares its diarization/ASD core with the **active-speaker / dynamic framing** thread (the same "who is talking" engine drives both *who to show* and *who to colour*), so the two are best built together.
  - Distinct from the **dialect store**, which handles *what* a single streamer says (accent/slang/names); this handles *who* among several speakers — orthogonal, composable.
- **Output organization & generated titles** — ✅ **Built (2026-06-28, ADR 0015).** Replaced `workspace/<video_id>/export.mp4` (a 2nd promote overwrote it) with a **stream folder** `workspace/<creator>/<stream-title>/` (sanitized from VOD metadata; local file = `local/<file-stem>`): rendered Shorts at the root, intermediates + `project.json` under `data/`. Each Short is named by an **LLM-generated ≤60-char title** emitted by the `yc-llm-judge` Qwen sidecar **at detect time** (it already reads the transcript — ADR 0010), stored on the `Moment`, threaded to render, sanitized + de-collided (` (2)`, `(3)`, …) so re-promotes never clobber; a manual/headless clip falls back to a `clip-<m-ss>` timestamp name. The four pinned decisions (detect-time title, collision policy, **`creators.json` defaults deferred to M7**, metadata-keyed analysis cache) are in ADR 0015. Touched `core`, `detect::llm`, `llm-judge`, `ingest`, `pipeline.rs`, `main.rs`. **Still open (the deferred half): the `creators.json` per-Creator defaults store** (seam / caption style / language / crops applied at Prepare/Render) — the folder hierarchy realizes Creator *scoping*, but the defaults system lands with **M7 Caption Styles**.

# Output organization: per-stream folders + LLM-generated Short titles

Until now every promote rendered `workspace/<video_id>/export.mp4`, so a second
promote of the same VOD **overwrote** the first, and the folder was an opaque
YouTube id. The operator asked for real output organization: human-readable
folders, one file per Short that never clobbers a previous one, and a separation
of the rendered Shorts from the pipeline's scratch. This ADR records that feature
and the four decisions pinned for it.

## Decision

A VOD now owns a **stream folder** `workspace/<creator>/<stream-title>/`:

- **Hierarchy.** `<creator>` and `<stream-title>` come from the VOD's metadata
  (yt-dlp `uploader`/`channel` and `title`; a local file is `local/<file-stem>`),
  each sanitized to one safe path segment. This **realizes Creator scoping** at the
  filesystem level — the long-deferred organization — without yet building a
  `creators.json` defaults store (see the decisions below).
- **Data / render split.** Rendered Shorts land at the stream-folder **root**; every
  intermediate (`analysis.wav`, `audio.m4a`, `segment*`, chat, `project.json`,
  `clip.ass`, the font) lives under a **`data/`** subfolder. ffmpeg renders with
  `data/` as its cwd (so libass still resolves `clip.ass`+font by relative name,
  dodging Windows drive-colon escaping) and writes the Short to an **absolute** path
  at the root one level up.
- **Per-export titles.** Each Short is named `<generated-title>.mp4`, not
  `export.mp4`, so re-promoting never clobbers a previous clip. The title is
  generated by the **`yc-llm-judge` Qwen sidecar at detect time** — it already reads
  each candidate's transcript to score clip-worthiness (ADR 0010), so it now also
  emits a catchy ≤60-char Shorts title in the same constrained-JSON object. The
  title is stored on the `Moment` (persisted in `project.json`), threaded through
  Prepare onto the held `PreparedClip`, and used to name the file at render.

## The four pinned decisions

- **LLM title at detect-time, not render-time.** Decisive: the ~5.4 GB judge GGUF
  **cannot co-reside with the GUI's wgpu renderer** on the 8 GB card (ADR 0010
  Outcome), and render runs from the GUI — so a render-time LLM call is infeasible
  without unloading the GUI. Detect-time is also nearly free (the judge is already
  loaded with the transcript in hand). A **manually-marked** Moment never goes
  through the judge, and a generation can omit/garble the title; both fall back to a
  deterministic **`clip-<m-ss>`** name derived from the clip's start (no LLM at
  render).
- **Collision policy:** sanitize the title → `<stem>.mp4`; if that exists, append
  ` (2)`, ` (3)`, … . An empty / all-symbol / emoji title (no alphanumeric survives
  sanitizing) first falls back to the `clip-<m-ss>` name, then de-collides. A
  re-promote of the same Moment therefore produces `Title (2).mp4`, never an
  overwrite.
- **`creators.json` — defer.** The folder hierarchy *is* the Creator scoping the
  operator wanted; a global store of per-Creator **defaults** (seam, caption style,
  language, crops — the `core::Creator` fields) is a separable, larger feature that
  must wire into Prepare/Render/the editor. It belongs with **M7 Caption Styles**,
  where the ROADMAP already places per-Creator caption defaults. Building it now
  would be a half-finished defaults system; the scoping win lands without it.
- **Analysis-cache key under the new hierarchy.** The cache key is now the stream
  folder's `data/analysis.wav`. Because `<creator>/<title>` is derived
  deterministically from VOD metadata, re-importing the same VOD lands in the same
  folder → the cached audio is reused (the behaviour we want). Two genuinely
  different VODs with an identical creator+title would share a folder; rare and
  operator-resolvable (rename), and not worth polluting the human-readable folder
  with a video_id.

## Considered options

- **Render-time title generation.** Rejected — the judge can't co-reside with the
  GUI (above); it would force a GUI unload per render. Detect-time, where the judge
  is already resident with the transcript, is both feasible and free.
- **Keep `export.mp4`, just move folders.** Rejected — the operator's core pain is
  the silent overwrite of a second promote; per-export filenames are the fix.
- **Title from the transcript's first words (no LLM).** Rejected as the default —
  it reads as a fragment, not a hook; the LLM already has the transcript and judges
  the moment, so it writes a real title. The transcript-derived idea survives only
  as the shape of the **timestamp fallback** (kept simple: `clip-<m-ss>`).
- **`video_id` in the folder name (collision-proof).** Rejected — defeats the
  human-readable goal; re-import cache-reuse and the rare title clash are acceptable.

## Consequences

- `core::Moment` gains `title: Option<String>` (`#[serde(default)]`, so a pre-0015
  `project.json` still loads). The detect path fills it from the judge; a manual
  Moment leaves it `None`.
- The judge IPC grows: `SYSTEM` asks for a `title`, the GBNF `GRAMMAR` constrains
  `{"score", "reason", "title"}`, `parse_output` returns a `Judgment {score, reason,
  title}` (tolerating a missing title), and `JudgeVerdict` carries `title`
  (`#[serde(default)]`). The judge's token caps rose (96→160, 512→1024 bytes) to fit
  the extra field. The load-bearing game-narration mitigation (ADR 0009/0010) is
  unchanged and still guarded by tests.
- `Job::Prepare` carries the promoted Moment's `title`; `PreparedClip` holds it so a
  re-render after a nudge keeps the name. `Session` splits `workdir` into
  `stream_dir` + `data_dir`. `build_clip` now records the export path on the `Clip`.
- New `yc_ingest::sanitize_segment(raw, fallback, max_len)` — pure, unit-tested:
  maps the Windows-reserved characters + control chars to `_`, collapses
  whitespace, caps by *character* count, trims trailing dots/spaces, guards the
  reserved DOS device names, and falls back when nothing usable remains. Folder
  segments cap at 64 chars, the title stem at 60 (under Windows MAX_PATH for
  `workspace/<creator>/<title>/data/segment.mp4` and the root Short).
- The output path is always **absolute** (joined to `stream_dir`), which also
  immunizes the ffmpeg output arg against a leading-`-` title being read as a flag.
- `--detect` prints each Moment's generated title; the GUI shows it in the review
  panel (the operator sees the Short's name before promoting) and threads it to
  Prepare on promote. Headless `--headless` (no detect pass) renders with the
  timestamp fallback.
- No migration: existing flat `workspace/<video_id>/` folders are gitignored
  scratch; the workspace was already empty.
- Touches `core`, `detect::llm`, `llm-judge`, `ingest`, and the app
  (`pipeline.rs` + `main.rs`).

## Outcome (2026-06-28)

Implemented and unit-verified. New/changed tests pass: `yc-detect` 34 (title parse,
missing-title tolerance, the `"title"` prompt clause guarded alongside the ADR 0009
mitigation), `yc-ingest` 14 (sanitize: separators, whitespace/dot trim, char-count
cap, reserved device names, empties), `yt-clipper` 5 (`stream_dirs` layout +
fallback, `clip_title_stem` title-vs-timestamp, filesafe `clock_stem`, `unique_path`
de-collision). Production app (default features) and the `yc-llm-judge` CUDA binary
both compile clean; `yc-transcribe`/`yc-render`/`yc-frame` unit suites stay green.
End-to-end on a real VOD with the GGUF (titles generated through the live judge) is
the operator's next run (paired with the streamer-curation loop).

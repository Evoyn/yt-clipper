# The thumbnail intro prepends AROUND the finished stream; the timeline runs in output time

Plan #5 (`feature-implementation-plan.md`: insert image, default 1 s editable, JPG/PNG/WebP, auto-fit the project aspect), queue-jumped ahead of title-gen by the operator (2026-07-13) in their own words: **"add new button to insert thumbnail, it will always insert for the first 1s-2s of the video, and make sure if user insert a thumbnail, everything bellow should follow how many seconds thumnail add, so the caption and camera cut doesnt error."** The operator ran the slice "automatic"; this ADR pre-registers the decisions BEFORE the build, on the fresh multi-track shell (ADR 0066 + amendments).

## Decisions

1. **Prepend around the finished main stream — never shift the data.** The thumbnail becomes a second ffmpeg input (`-loop 1 -t D -i img`), scaled/padded to 1080×1920 (aspect-fit, black bars — plan #5's "automatically fit"), `setsar=1`, `fps` matched to the probed source rate (30 fallback when unprobed), `format=yuv420p`, plus `anullsrc` silent audio; both audio branches pass `aformat` (fltp / 48 kHz / stereo) so concat's same-parameters rule holds for ANY source. The pair concats AHEAD of the main stream **after** its one post-concat ASS burn: `[introv][introa][main][maina]concat=n=2:v=1:a=1[out][aout]`. Captions, camera cuts, and razor spans stay source-relative BY CONSTRUCTION — the operator's "the caption and camera cut doesnt error" is structural, not arithmetic. The output `-t` bound extends to `D + dur`; with an intro the audio always maps from the graph (`[aout]`).
2. **The timeline shows the truth: output time `[0 .. D+dur]`.** The playhead and the Viewport run in OUTPUT time; a thumbnail block occupies `[0..D]` at Video 1's head (the CapCut prepend idiom — NOT a dead Images track; a real overlay track stays #14's arc, per ADR 0066 decision 1). Every source-anchored artifact (captions, rails, speaker bins, camera cuts, razor cuts/veils, the ▼ marker) draws through one intro offset applied at the strip's t↔x boundary (`s_to_x`/`x_to_s` beside the output-domain `t_to_x`/`x_to_t`); gestures subtract it back, so drag math stays source-domain. Time LABELS that name strip positions (panel timestamps, block/marker tooltips, the drag chip) show output time too — they match the exported video's clock; durations stay durations.
3. **Razor, marker, and camera verbs refuse inside `[0..D)`** — the intro is not razor-able source; the transport's scissors/Mark buttons disable with a tooltip while the playhead sits there, and the strip menu offers no cut verbs in that region. The block's right edge IS its duration control: drag trims `D`, clamped **0.5–2.0 s hard, 1.0 s default** (plan #5's default inside the operator's spoken 1–2 s window, with headroom below). Right-click removes or replaces; the body doesn't drag (always at the head). No new header card: the block is Video 1 content until a real Images track exists (ADR 0066 track-honesty).
4. **Preview parity without an image decoder.** The preview texture decodes through the pinned ffmpeg (one rawvideo call) using THE SAME scale/pad geometry as the render at half resolution (540×960) — the canvas during the intro IS the burn's frame (ADR 0036's promise), and ffmpeg covers JPG/PNG/WebP for free. The `image` crate stays out (deliberate, `crates/app/Cargo.toml`). Parked inside the intro the canvas shows the thumbnail; the caption overlay and camera chip show nothing (nothing burns there). Play from inside the intro holds the image on the wall-clock anchor for the remainder of `D`, then spawns the live decode at source 0 and starts audio through the existing `video_aligned` re-anchor — the machinery that already models "video not started yet". Scrubs/jumps into the intro stop audio (silence is the truth there); crossing `D` restarts it — the same restart contract as today.
5. **Persistence now: `Clip.thumbnail: Option<ThumbnailIntro { path, duration_s }>`** in project.json — the ADR 0066 decision-6 pre-registered moment (track contents become data). A picked file path is durable operator data, serde-defaulted so every pre-intro project.json loads unchanged. The image is REFERENCED, not copied. Missing file on a future load = drop the intro with a note, never a crash; missing at render time = fail loudly with the path (the operator asked for it — silently shipping without would lie).
6. **`RenderSpec` and `Job::Render` gain `intro: Option<ThumbnailIntro>`**; batch/headless renders pass `None` — args and graph byte-identical to today, test-pinned.

## Considered and rejected

- **Adding +D to every caption/shot/ASS event** — touches every time consumer, re-shifts on every duration edit, and turns one structural fact into N arithmetic obligations.
- **A dead Images track header** — ADR 0066 decision 1: a track arrives WITH its render machinery; this block is Video 1 content.
- **The `image` crate for the preview texture** — the app deliberately ships no image decoder; ffmpeg already is one.
- **Skipping the intro when Play starts inside it** — the preview must play what the render shows; the hold-then-start is the export's own behavior.
- **Copying the picked image into the workspace** — silently duplicating operator files is surprising; the reference + missing-file rules above are the honest contract (revisit if stale-path reports arrive).
- **Keeping panel timestamps in source time** — a caption "at 3.2 s" sitting under ruler 4.2 s makes two clocks; output labels match the exported video.

## Bars (pre-registered before the build)

- Filtergraph tests: the intro prepend sits AFTER the one `subtitles=` (count stays 1); concat pairs v+a into final `[out]`/`[aout]`; `export_args` insert the image input, extend `-t` to `D + dur`, and map the final labels; the ASS bytes are IDENTICAL with and without an intro (`generate_ass` never sees it; the main chain survives byte-for-byte modulo the terminal label rename); razor + camera + intro compose in one graph.
- Editor tests: display-offset round-trip (a block at source t draws at t+D; a gesture at that x edits source t); duration clamp at 0.5/2.0; razor verbs refuse inside the intro; `render_spec` carries the intro only when set; output-duration math.
- The burn gate (the operator's eye, on a REAL export): thumbnail head 1–2 s, first caption lands exactly on its word, a camera cut and a razor cut land where the strip shows them. Gate on the burn, not the preview.

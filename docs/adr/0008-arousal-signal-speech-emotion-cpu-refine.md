# Arousal Signal: CPU speech-emotion in refine, ahead of the LLM rerank, gated on mixed audio

Spike/loudness detection finds *loud*, not *emotionally clip-worthy*, moments — a streamer's reaction and a game explosion look alike to RMS. The next detection deepening is therefore semantic, and the operator asked for a speech-emotion model "next." We decided to add an **arousal** Signal: a CPU speech-emotion (SER) model scores how emotionally *activated* the streamer's voice is, in the **refine** phase, and this lands **ahead of** the ROADMAP's LLM rerank. The catch both semantic signals share is the mixed-audio limitation (ADR 0007): the analysis wav carries game + streamer, and the loudest voice is often the game — so an SER model could score the game's emotion and an LLM could read the game's transcript. Rather than gate on vocal separation up front, we **validate arousal on real mixed audio first**; if it fails, vocal separation is promoted ahead of further semantic work. This extends ADR 0002 (signals stored unblended) and ADR 0007 (cheap discovery, bounded candidate refine).

## Considered options

- **LLM rerank first (the ROADMAP M4 order).** Rejected as the immediate next step: the LLM reads whisper's transcript, which is the *same* mixed-audio-corrupted text, so it inherits the wrong-speaker problem without addressing the operator's actual complaint (loud-but-flat false positives). Arousal attacks that false positive directly and is far cheaper to stand up. The LLM rerank stays the *following* milestone.
- **Vocal separation first.** ADR 0007 argued separation only corrupts the lexicon (loudness is even helped by the mix) and so does not gate M3. The new phase is all semantic, so separation would now corrupt the *majority* of new signals — a real reason to revisit. Rejected as an up-front gate anyway: it is a large milestone (an ingest-time stem, its own model, its own ADR + spike) and may be unnecessary if the streamer's mic is present enough in the mix. We keep it as the **contingency the gate can trigger** rather than a prerequisite.
- **SER on the GPU, staged with whisper.** Rejected: the model is a 12-layer pruned wav2vec2 scoring only a handful of short candidate windows. Running it on the **CPU** sidesteps the 8 GB sequential-staging puzzle entirely (it is not a GPU stage, so "GPU stages strictly sequential" holds trivially) and avoids any ORT/CUDA-version coupling. The CUDA execution provider remains a one-line `ort` session change if CPU ever proves too slow.
- **Categorical or valence SER.** Rejected: clip-worthiness needs *activation*, not *which* emotion — a laugh and a rage are both clips, so distinguishing them buys nothing for ranking. Arousal is the axis; valence (positive-vs-negative, e.g. a future toxicity/positivity bias) is deferred.
- **Whole-VOD SER as a discovery signal now.** Deferred to an immediate fast-follow: a neural pass over the whole VOD every detect run erodes ADR 0007's "discovery is cheap and GPU-free" principle. Refine-SER ships first and the gate validates the arousal signal *before* we invest in discovery. The SER inference is factored as an arousal-over-a-sample-range primitive (mirroring `loudness::read_rms_bins`) so the discovery pass reuses it.

## Consequences

- A new Signal **`arousal`** joins `core::Signals` (alongside `chat_rate`, `loudness`, `lexicon`, `llm`), stored unblended and z-scored across the candidate set, then weighted into `combined_score` — retunable without re-analysis, exactly like the lexicon (ADR 0002). The combine and `Weights` gain an `arousal` term.
- Net-new dependency: **`ort`** (ONNX Runtime bindings, **CPU** execution provider) — also the runtime M5 plans for facecam detection, so not a one-off. Model: **audeering `wav2vec2-large-robust-12-ft-emotion-msp-dim`**, ONNX export (Zenodo `doi:10.5281/zenodo.6221127`), which takes **16 kHz mono** audio — the exact format of `analysis.wav`, so no resampling. Lives in `models/`; its download is operator-gated. License is research/non-commercial — acceptable for this offline personal tool.
- In **refine**, per candidate: slide a short window (~4 s, ~2 s hop) across the candidate range and **max-pool** the arousal (parallel to the max-pool loudness of ADR 0007 / commit `9d763ef`, so a brief 2-second scream surfaces rather than being averaged away), yielding one arousal score per candidate. SER reads audio directly, so it is independent of the whisper transcript and runs after the resident Transcriber is dropped.
- Refine-SER **re-ranks** candidates but cannot **surface** a quiet-emotional moment that was neither loud nor chatted. The pre-committed fast-follow is a whole-VOD arousal bin-series fed into discovery's peak-detection (reusing the same primitive). Manual Moment marking backstops in the meantime.
- **Mixed-audio gate** (the decision the operator asked to make by evidence): dump per-candidate arousal next to loudness on the real VOD `ZSegfmsrYmE` via `crates/detect/examples/detect_vod.rs`. PASS if arousal ranks known emotional reactions **above** known loud-but-flat moments; if it inverts (game/music outscores reactions), vocal separation is promoted ahead of further SER/LLM work.
- **ROADMAP reorder:** M4 becomes the Arousal Signal; the LLM rerank shifts to M5; Framing/Caption Styles/Hardening shift to M6/M7/M8.

## Outcome (mixed-audio gate, 2026-06-18)

**PASS — arousal works on the mixed track; vocal separation stays deferred.** Validated on `ZSegfmsrYmE` (66 min) with `--features ser` via `detect_vod` (refine re-rank), `arousal_scan` (whole-VOD distribution), and `arousal_probe` (dense local trace):

- Whole-VOD arousal has a wide range (min −0.04, median 0.67, p90 0.91, max 1.10): quiet/flat stretches score ~0, so the game is **not** drowning the streamer (that failure mode would read uniformly high).
- Densely probed, genuine reactions **peak high**: the 39:38 jumpscare reaches 0.94 (follow-up burst 1.07), the 55:04 moment 1.10, each decaying to ~0 in the surrounding pauses — tight temporal discrimination.
- Reactions sit at only **moderate loudness** (RMS ~0.37–0.45), so arousal adds signal beyond loudness despite a global `r(arousal, loudness) = 0.79` (the correlation is co-moving speech energy, not redundancy at the peaks).
- **Max-pool is vindicated**: a candidate's peak 4 s window captures its reaction (~1.0); a loud-but-flat candidate has no such window and pools lower (the 45:23 demotion). The compression seen on loudness-only candidates was because they are all reactive, not a pooling fault.
- CPU cost: ~0.35–0.46 s per 4 s window (~163 s for the 25-candidate refine batch). Acceptable for a background detect; the CUDA EP remains a drop-in if needed.
- **Next:** the pre-committed whole-VOD arousal *discovery* pass (peak-detect the `arousal_series` to surface quiet-emotional moments loudness underranks — e.g. 55:04 at RMS 0.37).

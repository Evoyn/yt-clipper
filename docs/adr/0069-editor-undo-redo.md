# Editor undo/redo: document snapshots on a 100-step ring, one push per gesture

The operator closed the music burn gate (ADR 0068 amendment) and picked undo as the next arc, in their own words: **"next we will work on undo since it doesnt have it right now, do we need to put max number for the undo to save resources?"** Not in `feature-implementation-plan.md` — their own ask, queued ahead of title-gen again. Their question is decision 2: yes, a cap — 100 steps — but for creep-proofing, not because snapshots are big. Run "automatic" (2026-07-13); this ADR pre-registers the decisions before the build.

## Decisions

1. **Snapshot/memento over command inverses.** One `Snapshot` struct = clones of the DOCUMENT fields only: `transcript` + `transcript_dirty` (the dirty flag IS document state — it decides whether the render burns the operator's text), `manual_units` + `manual_places` (the 1:1 pairing rides as a pair), razor `cuts` + `removed`, `cut_marker`, `plan`, the framing set (`kind`, `seam`, `gameplay`, `facecam`, `fullcam`, `fullgameplay`), `style` + `preset`, `placement`, `camera_mode`, `motion`, the intro as `(path, duration_s)` — the texture is derived — `music`, and the track flags (`trk_auto`, `trk_manual`, `trk_music`, `speakers_eye`). `fn snapshot(&self)` + `fn restore(&mut self, …)` on `EditorState`; no field-move refactor. Everything else is deliberately OUTSIDE history: view state (`viewport`, `view`, `show_captions`, `show_safe_area`), transport (`playhead_s`, `playing`, `live`), selections (`sel_unit`, `sel_manual`, `sel_music`), one-shots (`focus_caption`, `scroll_to_sel`, `strip_menu_t`), worker artifacts (`speakers`, `faces`, `voice_note`, `frames`), derived caches (`lines`, `overlay_cache`, `music_pcm`, intro `tex`), and settings.json content (saved presets, volume). Undo must never "undo" a scroll, a park, or a selection — the operator's CapCut hands expect content edits only.
2. **The cap: `undo: VecDeque<Snapshot>` at 100, drop-front; `redo: Vec<Snapshot>` cleared on every landed push.** Snapshots are a few KB to ~100 KB (dominated by caption text; the heavy things — ~40 MB decoded PCM per song, filmstrip/intro textures — are derived caches keyed by path and are never cloned). 100 × ~100 KB ≈ ≤10 MB worst case: the cap exists so a thousand-edit session can never creep, not because snapshots are big (Premiere ships 32, Photoshop ~50). Undo = push current onto redo, pop + restore; redo mirrors; both stacks are session-only and never persisted (the ADR 0066 decision-6 scope: nothing here touches project.json or any export path).
3. **One choke point per mutating family, one step per operator intent.**
   - *Timeline gestures*: a `begin_drag(&mut self, d: TimelineDrag)` helper snapshots-then-sets, replacing the five direct `self.drag = Some(…)` sites (blocks/edges via the accumulated `begin_drag` local, `begin_cut`, `begin_razor`, the ▼ marker, the intro edge). A 60-frame drag lands ONE snapshot, at the None→Some transition.
   - *Canvas per-frame writes* (crop pan/zoom, corner resize, seam, the AS-shot reframes, caption placement drag/scroll-resize, manual-caption placement): copy-mutate-compare-writeback where aliasing allows, and a burst coalescer for all of them — `undo_burst(key, ui)` opens a new step when the key, the pointer-press sequence number, or a ~1 s idle boundary changes; otherwise the burst continues and nothing is pushed. A no-op gesture (grabbed, never moved) pushes nothing because the writeback is change-detected; equal-to-top pushes are dropped besides.
   - *Panel widget sessions*: `gained_focus()` / `drag_started()` on `TextEdit`/`DragValue` rows mark one push per editing session (one step per text edit, not per keystroke); the style-knob block reuses its existing `before = style.clone()` compare — the pushed snapshot carries `before`, so the pre-knob state is exact even though egui mutates in place; knob drags coalesce on the same burst mechanism.
   - *Verbs* (each = one step): push inside the verb methods after their refusal guards (`add_caption_at_playhead`, `remove_manual_caption`, `add_music`/`place_music_clip`, `remove_music`, `trim_music_*`, `split_music_at`, `split_shot_at_playhead`, `delete_cut`, `reset_to_auto`, `click_face`), and at the click site where the mutation is inline (razor cut/toggle/delete via a pre-verb `razor.clone()` riding the snapshot only when the verb reports a change, ⏷ Mark, marker clear, camera-mode/kind/motion/preset picks, placement reset, track toggles, intro replace/remove, the Manual-takeover drag, panel row verbs, strip/block menus, Delete key routing, arrow-key crop nudges — nudge bursts coalesce like knobs so a held key is one step).
4. **Restore heals the derived world, never trusts stale references.** `restore` sets `drag = None`, `lines_dirty = true`, `overlay_cache = None`, `panel_sort_pending = false`; clears the three selections and the one-shots; clamps the playhead to the possibly-changed `out_dur`; `refresh_camera_audit()`. The intro re-decodes through the `set_intro_image` path only when the path actually changed (same path = keep the texture, take the duration). Music PCM heals through a new `ensure_music_pcm` (the decode half of `add_music`): after undoing a music delete the PCM may be evicted — re-probe + decode at restore, so the clip returns AND plays (`music_cues` skipping PCM-less clips remains the last-ditch guard, not the plan). If playback is live, restore returns the one restart action (`restart_playback`) so voice + music re-cue against the restored document — the ADR 0068 one-restart contract.
5. **Keys + transport.** Ctrl+Z / Ctrl+Shift+Z / Ctrl+Y land in `handle_keys` — which already runs only when NO widget has focus, so egui's own in-field text undo stays intact inside text boxes. ↺ / ↻ transport buttons beside Play with tooltips showing depth ("Undo (Ctrl+Z) · 12 steps") and honest disabled states; glyphs are subject to the tofu rule (ADR 0065 Am. 5) — the operator's eye decides at the feel gate, painted arrows are the fallback. An in-flight timeline gesture is landed (`finish_timeline_drag`) before an undo applies — never restore under a live drag. Undo/redo reset the burst state, so a drag that straddles an undo starts a fresh step.
6. **Worker arrivals never push.** `set_captions` / `set_speakers` are not operator ops; `set_captions` already refuses over a dirty transcript. Consequence, accepted and documented: undoing past an arrival restores the older document (e.g. `plan = None`, the pre-analysis camera mode) — redo returns it, a fresh analysis re-delivers it. This is standard NLE behavior (the document at that step truly had no plan) and the honest reading of "snapshots of the document".

## Considered and rejected

- **Command-pattern inverses** across ~40 scattered mutation sites — miss one site and undo corrupts silently; the memento's failure mode is "a field wasn't restored", which the round-trip test pins instead.
- **Persistent structural sharing (`im` crate / Arc-COW fields)** — overkill at ≤100 KB per snapshot; adds a dependency and a new idiom for zero felt difference at these sizes.
- **Unbounded history** — the operator asked about resources; unbounded is how a thousand-edit session creeps to nonsense. 100 is far past any real regret horizon.
- **Pushing on worker arrivals** — a background delivery is not an operator intent; Ctrl+Z immediately after an arrival must undo the operator's LAST EDIT, not silently swallow the analysis.
- **Snapshotting selections/viewport** — undo that teleports the scroll position or re-selects a row reads as haunted; CapCut/Premiere agree.
- **Time-window-only coalescing** (no press-sequence) — two quick, distinct drags of the same crop would merge into one step; the pointer-press sequence number keeps gestures separate at zero cost.

## Accepted trade-offs (recorded, not hidden)

- A refused verb (e.g. razor refusing to remove the last kept segment) or a truly no-op panel session can clear the redo stack without landing a step (equal-to-top pushes are dropped; an undo that finds top == current skips the duplicate silently — so Ctrl+Z never feels dead). New-edit-clears-redo is the mental model anyway.
- A `DragValue`/slider flick that moves on its very first frame loses that first sub-tick to the pre-push (the deferred push runs after the row loop); bounded by one frame at drag speed — hundredths of a unit.
- Two same-key scroll-resize bursts under ~1 s apart merge into one step (no press boundary exists for scroll).

## Bars (pre-registered before the build)

- One gesture = one step, per family: a multi-frame timeline drag lands one snapshot (`begin_drag` on None→Some); a canvas crop drag one; a text/DragValue editing session one; every verb one. A representative test per family (razor verb, caption drag path, panel edit path, music verb, style knob, intro trim).
- Undo→redo round-trips the document byte-equal (`PartialEq` on `Snapshot` pins every field); restore resets the derived/selection invariants (drag None, `lines_dirty`, selections cleared, audit refreshed).
- The cap: pushing 150 steps holds 100, oldest dropped, no panic; a new edit after undo clears redo.
- Music-delete undo: the clip returns AND its PCM heals (`ensure_music_pcm` re-decodes; the spec carries the clip) — the ADR 0068 handoff watch-out closed.
- Byte-identity: with zero undo activity, `render_spec` and every export path are untouched (undo is editor-session state, never persisted); with undo activity, `render_spec` reflects exactly the restored document.
- The feel gate (operator): Ctrl+Z after each of their real edits does what CapCut taught their hands; nothing undoes a scroll/zoom/park/selection; the ↺/↻ glyphs render (tofu rule) or get painted replacements.

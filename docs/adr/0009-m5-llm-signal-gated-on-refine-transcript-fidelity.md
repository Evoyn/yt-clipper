# M5 LLM judgment Signal: gated on refine transcript fidelity (streamer vs game)

ROADMAP M5 is the local-LLM rerank (ADR 0002): a GGUF model served by llama.cpp reads each refine candidate's transcript window and scores clip-worthiness. Mechanically this is **the LLM judgment Signal** — `core::Signals.llm` already exists (scaffolded, unpopulated), the refine loop already builds the per-candidate `texts`, and `pipeline.rs` already `drop`s the Transcriber "before any later GPU stage (M5 LLM)". So M5 slots in exactly like arousal did (ADR 0008): a new `Weights.llm` term, one row in `combined_score`, a per-candidate scorer — **not** a separate post-sort "rerank" stage. We treat "LLM rerank" and "LLM judgment Signal" as the same thing.

The catch is the mixed-audio limitation (ADR 0007, ADR 0008): the analysis wav carries game + streamer, and the loudest voice is often the game. Arousal (ADR 0008) reads **audio**, so vocal activation survives the mix — a loud reaction is loud regardless of whose words whisper caught. The LLM reads **text**, so if whisper transcribed the game's dialogue, the LLM's *entire* value (semantic judgment of what the **streamer** said) is spent judging the wrong speaker. The wrong-speaker problem therefore hits the LLM **harder** than it hit arousal.

ADR 0008 measured transcript fidelity for the **discovery** population and found it sank on quiet game cutscenes (4 of 12 off-diagonal candidates). It never measured the **refine** population — the loud/chatted candidates, which *exclude* those quiet cutscenes, so the streamer is usually present. That single unmeasured datum (how often a refine candidate's transcript is the streamer vs the game) decides whether M5 is worth building now. We decided to **measure it first**, and gate the M5 build on the result, rather than build llama.cpp blind or promote vocal separation without evidence.

## Considered options

- **Build M5 now, gate post-build** (mirror the arousal gate). Rejected as the lead step: it commits the whole milestone — a new crate, a llama.cpp CUDA build mirroring whisper's, an operator-gated ~5 GB GGUF download — before knowing the crux. The LLM code is reusable once vocal separation lands, so a failed gate is re-validation not rework, but the build effort is still spent to learn a "no" that a cheap read answers first.
- **Vocal separation first** (leapfrog M5). Rejected as premature: vocal separation is a large milestone in its own right (its own model, ADR, spike, an ingest-time stem and VRAM/latency budget), and ADR 0008 deliberately kept it the *contingency a gate can trigger*, not a prerequisite. Refine candidates are pre-filtered to loud/chatted gameplay (streamer-present), so the wrong-speaker hit may be small — measure before paying for the keystone.
- **Measure refine transcript fidelity first** (chosen). Cheap (one GPU detect + reading 25 transcripts), reuses the existing harness pattern, and is exactly how ADR 0008 resolved the discovery question. The measured rate decides M5-gated vs vocal-separation-first, with the goalposts pinned below before any result is seen.

## Consequences

- New harness `crates/app/examples/refine_transcripts.rs` dumps the **real** chat+loudness top-25 (`DetectParams::default`, identical to `do_detect`, so the dumped set *is* the population the LLM would judge) with each candidate's transcript plus its chat/loudness/lexicon/arousal context. App-crate (like `arousal_adds`) so the no-GPU `test -p yc-detect` path stays whisper-free.
- **Classification:** each candidate's transcript is labelled **Streamer / Game-dramatic / Game-mundane / Mixed / Empty-nonlexical**, by reading first and escalating ambiguous cases to the review UI's volume-boosted playback (the volume slider shipped for exactly this). Metric: the **usable-streamer fraction** (the share on which the LLM judges the right speaker) and the **game-dramatic fraction**.
- **Gate (pre-committed):** **PASS — build the M5 LLM judgment Signal (gated)** if usable-streamer ≥ ~70% **and** game-dramatic ≤ ~15%. **FAIL — promote vocal separation ahead of M5** if usable-streamer ≤ ~50% **or** game-dramatic ≥ ~30%. The middle band is an operator judgment, weighing whether the game transcripts are dramatic or benign.
- **Why two parts, not one streamer-fraction cut:** a game transcript is not neutral. *Empty/non-lexical* is benign (the LLM scores a non-speech beat low, which is roughly correct). *Game-mundane* (menu text, ambient chatter) mildly dilutes. *Game-dramatic* (scripted boss taunts, emotional cutscene lines) **actively misleads** — it reads as highly clip-worthy and inflates the very loud-but-flat false positives arousal exists to suppress. So game-dramatic is weighted heavier against M5 than mere streamer-absence.
- **Corpus:** `ZSegfmsrYmE` (cutscene-heavy story game — the worst case for transcript contamination, so a PASS generalizes safely). Branch to one low-dialogue VOD only if the result is middle-band or surprising.
- **If PASS,** the M5 build design is grilled then, not now: GGUF model choice (must fit 8 GB after the whisper `drop`, and be strong at EN/ID/JA — the transcripts are multilingual), the llama.cpp binding crate and its CUDA build wiring, the prompt shape over the transcript windows, sequential VRAM staging after the existing `drop(transcriber)`, a `--features llm` flag mirroring `ser`, and the `Weights.llm` default. A documented mitigation lever for residual contamination: feed the LLM the corroborating per-candidate signals (loudness/chat/arousal) and instruct it to discount scripted game narration, so it is robust-by-corroboration rather than betting everything on the words.
- **If FAIL,** vocal separation becomes the next milestone (its own ADR + spike), and the LLM judgment Signal follows it — built once, on clean streamer-only transcripts. This also lifts the lexicon and captions, which share the same ceiling.
- Extends ADR 0002 (signals stored unblended, retunable) and ADR 0007/0008 (cheap discovery, bounded refine, vocal separation as a gated contingency).

## Outcome (2026-06-18)

**PASS — build the M5 LLM judgment Signal (gated).** Measured on `ZSegfmsrYmE`'s 25 refine candidates via `refine_transcripts` (the real chat+loudness set: 39,125 chat messages, lang Id). Classifying each transcript:

- **Streamer: 19/25 (76%).** The streamer (Brando) dominates the loud/chatted candidates — reactions ("Kaget mampus", "What the heck is that?"), hype ("Let's go", "Gila jenius"), viewer shout-outs / name-reading (#10, #16, #22), chat banter (#14, #23). The mixed-audio fear (the game drowning the streamer) does **not** materialize in the refine population, exactly as hypothesized: refine pre-filters to loud/chatted gameplay, which is precisely where the streamer is talking.
- **Mixed: 3/25 (#6, #9, #25).** The streamer reading in-game documents (clinical reports) aloud, interleaved with reactions — streamer-voiced and usable. Counting these as usable puts the streamer-usable fraction at **88%**.
- **Game-dramatic: 3/25 (12%).** The predicted anti-signal — scripted cutscene/intro dialogue with the streamer silent: #21 (the opening James/William story hook), #11 (the emotional ending: "Kau memanggilku putra… aku hanyalah anak kesepian di kursi listrik. No!"), #12 (villain scheming). **#11 carries the highest arousal in the whole set (1.107)** — concrete confirmation of the theorized risk that a dramatic game line scores high on the non-semantic signals.
- Game-mundane / Empty: 0.

Gate: usable-streamer 76% (88% incl. Mixed) ≥ 70% ✓ **and** game-dramatic 12% ≤ 15% ✓ → **PASS**, robustly (failure needed ≤50% streamer or ≥30% dramatic; neither is close). `ZSegfmsrYmE` is the cutscene-heavy worst case, so the PASS generalizes — no second VOD needed.

**Consequence:** proceed to build the LLM judgment Signal in refine. The validated #11 case (highest arousal in the set sitting on scripted game dialogue, streamer silent) makes the mitigation lever **load-bearing, not optional**: the LLM should receive the corroborating per-candidate signals and be instructed to discount scripted game narration, so a dramatic cutscene line cannot inflate its score the way it inflates arousal. The M5 build design (GGUF model, llama.cpp binding, prompt shape, sequential VRAM staging after the whisper `drop`, a `--features llm` flag, the `Weights.llm` default) is grilled next.

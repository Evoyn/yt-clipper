# The timeline becomes a multi-track shell: header column, honest per-track toggles, and a zoom/scroll viewport

Plan #13 (`feature-implementation-plan.md`), the operator-picked arc after editor-suite slices 1–8 (ADR 0064/0065), opened with two rulings in their own words (2026-07-13): **"mimic adobe or tiktok"** — the Premiere/CapCut shape: track headers in a left column, lanes to the right, wheel scrolls, zoom around the pointer — and **"keep the independent track: if it get generated by ai it must have their own track, if it by me it must get its own track."** The operator ran this slice "automatic"; this ADR pre-registers the track model and viewport decisions BEFORE the rewrite, so later arcs (#5 images, #6 music, #14 B-roll, nested timelines) inherit them instead of re-deciding them.

## Decisions

1. **The track shell rehomes what exists; a track arrives WITH its render arc, never before.** The strip gains a fixed header column (name + toggles) and rehomes today's honest rows as tracks: **Video 1 · Main** (the filmstrip), **Captions · auto** (the pipeline's stream), **Captions · yours** (the operator's stream, ADR 0065 Amendment 3), the **Speakers** analysis zone, and the camera-badge gutter (Active Speaker mode). Music/Images/SFX/B-roll tracks do NOT appear until their ffmpeg machinery lands — an unmutable Music track or an un-hideable Image track is dead UI lying about the export. Tracks therefore arrive incrementally, each with its arc.
2. **The AI/operator separation is architectural, not a caption quirk.** An AI artifact and an operator artifact never share a track; the two caption tracks are the first embodiment, and every future generated-vs-placed pair (auto B-roll vs dropped-in B-roll, AI music beds vs imported music) splits the same way. Dragging a clip BETWEEN tracks (plan #13's requirement) is a same-kind, same-ownership move and waits for a second track of some kind to exist; dragging an AI caption onto the operator's track would change OWNERSHIP, so it is forbidden as a silent gesture — if it ever exists it is an explicit "take over this caption" verb (copy to yours + delete from auto), pre-registered here, deliberately not built.
3. **Per-kind honest toggles — only a toggle whose OFF state is real today appears** (the operator's own sketch already varies toggles per row):
   - **Eye = output visibility: the preview overlay and the burn together** (the preview cannot drift from the burn, ADR 0036). Captions·auto eye off → `RenderSpec.transcript_override = Some(empty transcript)`; Captions·yours off → `RenderSpec.manual_captions = []` — the spec already SAYS what burns, so "burn none" is expressed in the spec's own vocabulary and the render path changes by zero words. The Speakers eye hides the analysis lanes (pure view — analysis never burns). **Video 1 gets no eye**: with a single video track, hiding the only video would export nothing.
   - **Lock = that track's TIMELINE gestures are ignored** (block drag/trim, rail drag, right-click delete, the transport's `＋ Caption` insert). The caption PANEL stays live — it is the deliberate precision surface, not the mouse-slip surface lock exists to guard — and preview-canvas placement drags stay live (placement is a canvas property, not a timeline one).
   - **Mute is deferred to the audio-mixer arc** (#7's future section). The only mute-bearing track today is Video 1, and muting the export's only audio is real render machinery (volume=0 through the filtergraph) plus an honest preview mute — mixer work. A 🔇 that muted only the preview would lie about the burn; none appears until the arc lands.
   - An eye-off track's blocks stay visible and editable on the strip, drawn dimmed (Premiere semantics: output visibility ≠ timeline visibility; hide-but-edit is the point of eye vs lock). Per-lane burn warnings (huge-word zero-display, manual overprint) are computed only for streams that burn.
   - The toolbar "Captions" chip stays the view-only declutter (hides the whole overlay, export untouched); the track eyes are output toggles. The tooltips name the difference.
4. **The viewport is a pure model: `Viewport { zoom, left_t }`**, zoom ∈ [1, dur/1s] (1 = the whole clip fits; max keeps ≥ 1 s visible), every strip t↔x conversion goes through it (the ADR 0064-deferred zoom/scroll work). Ctrl+wheel / pinch zooms about the pointer (`egui zoom_delta`); plain wheel, shift+wheel, and trackpad-x scroll horizontally; a bottom scrollbar row (thumb = visible fraction) appears interactive when zoomed. Snap tolerances stay in POINTS (SNAP_PX converts through the visible span, not the clip). The filmstrip picks thumbs for the VISIBLE range by construction (slot centers go through `x_to_t`). The playhead auto-follows during playback (pages when it exits the view); seek-jumps (arrow keys, caption clicks) call `ensure_visible`. Mid-gesture scroll/zoom is safe by construction: `TimelineDrag` gestures are pointer-tracked in TIME (`grab_t`), re-derived from the pointer's x each frame — the ADR 0064 pattern this rewrite deliberately keeps, along with magnet snapping, painted markers, and the playhead > markers > blocks > scrub priority order.
5. **Track order is z-order for video-kind tracks: top = above.** Video 1 sits top today; when #14's B-roll lands it slots ABOVE Video 1 and the render's overlay order reads straight off the header column. The caption lanes keep their operator-approved order (auto above yours, round-5 verdict) — they are simultaneous streams at independent anchors, not composited layers, so z-order does not bind them.
6. **Persistence: track flags and the viewport are editor-session state, deliberately** — the same scope as `manual_units` today. Pre-registered schema question for the arcs that add track CONTENTS (music files, image paths): those move track state into project.json's Clip, and the static named flags become a `Vec<Track>` — the track LIST becomes data exactly when track contents become data, not before.

## Considered and rejected

- **A generic `Vec<Track>` model now** — pretend-generality: no track can be added/removed/reordered by the operator yet, and there is no content to carry. Named flags are the honest shape until contents exist (decision 6 names the promotion point).
- **A new `burn_auto: bool` through RenderSpec/Job::Render** — the spec already expresses what burns; `Some(empty)` / `[]` are the literal truth and touch zero pipeline signatures.
- **Mute on Video 1 now via `volume=0`** — real render work belonging to the mixer arc; shipping the icon before the machinery is the dead-UI lie decision 1 exists to prevent.
- **Hiding an eye-off track's blocks from the strip** — conflates eye with lock; Premiere keeps hidden tracks editable, and so does this shell.
- **Persisting zoom/scroll in `workspace/settings.json`** — view state, not project state; a stale zoom on open reads as a broken timeline.
- **Emoji glyphs (👁 🔒) for the header toggles** — the round-6 tofu lesson (ADR 0065 Amendment 5): only egui's emoji fonts back the UI font, so the toggles are PAINTED shapes, font-proof.

## Amendment — boxed headers (operator round-2 verdict, same day)

The operator drove the shell and ruled it "plain — maybe have a box style so it will symetrical with the track timeline (same size between title and actual track)". The headers became **cards**: each a rounded box spanning EXACTLY its track's lane band, with a kind-colored accent edge — blue (INFO) = video, gold = the pipeline's captions, green (`theme::OK`) = the operator's own, gray = analysis — that dims when the track's eye is off. The lanes mirror the cards with row bands + hairline separators so header and lane read as one continuous bar, and the caption blocks now tint by their track's accent (the CapCut colored-track idiom; radius 4). Caption lanes grew 18 → 22 px (blocks 18 px tall, 2 px inset) so the cards breathe; chrome is 125. The zoom corner buttons restyled to match the cards. Pure look — every toggle, gate, and gesture from the shell round is byte-identical in behavior. Same-round follow-up ("the text feels odd... maybe increase the size"): the card labels were 9.5 pt against the theme's 15 pt transport buttons — raised to 12 pt (the theme's Small), the header column widened 118 → 158 px to carry them, icon/label spacing and the zoom corner scaled to match. And ("make the text symetrical... always upper case for the first letter"): every name sits in one label column (x = 44, clear of the icon slots — icon-less cards keep the empty gutter, the Premiere alignment), and the caption tracks read **Captions · Auto** / **Captions · Yours**.

## Validation

Viewport math unit-tested (t↔x round-trip under zoom+scroll, zoom-about-pointer keeps the anchor time, clamps at the clip edges, min-span floor, follow/ensure-visible paging); `render_spec` eye tests (auto off → empty override even when dirty, yours off → empty manual stream, eyes on → byte-identical to today); `nice_step` gains sub-second ruler steps, pinned. `cargo test` green on yt-clipper/yc-core/yc-render; clippy + `--features face,align,ser` check clean. The feel gates — zoom about the pointer, wheel scroll, drag-under-zoom, header toggles, and an eye-off export honestly missing that stream — are the operator's eye on the release build (gate on the burn, not the label).
